# Story 05 — Working-model rail

## User story

As a potential client, I want a practical sense of how engagement works so that starting a project feels less ambiguous.

## Scope

- Create the `Approach` section as a four-stage rail: Frame, Make, Integrate, Release.
- Explain what happens, who is involved, and the artifact each stage produces.
- Pair the active stage with a small, abstract process artifact such as a checklist, annotation, or system sketch.

## Acceptance criteria

- Desktop uses a horizontal rail; mobile uses an equivalent vertical sequence.
- A stage has clear selected/hover/focus behavior; selecting it does not hide essential information.
- Transitions are 160–220ms and only clarify state; there are no looping timelines or scroll-driven effects.
- Every stage uses plain-language descriptions and avoids guaranteeing timeline, delivery, or performance outcomes.
- The result feels like a clear method, not a generic four-card process grid.

## Out of scope

- Sprint calendars, project estimates, client portals, or commitments that require operational approval.

## Dependencies

- Story 01; anchors supplied by Story 02.
